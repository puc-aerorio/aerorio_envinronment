# Host networking on every Host, never published ports

The Container always runs with host networking, on Linux Hosts and WSL Hosts alike; no port is ever published with `-p`. Publishing only uav-api's `:8000` (tried once, so a Windows browser could open `/docs` under Docker Desktop) cuts off everything else that talks to the Simulation from the Host: Ground Stations on UDP 14550, the SITL's TCP ports, and Gazebo's transport, whose discovery doesn't survive a bridge network. Publishing each of those instead would be a second network configuration to keep in sync. On a WSL Host with Docker Engine in the distro, host networking already makes `localhost:8000` reachable from Windows through WSL's localhost forwarding. With Docker Desktop, team members turn on its "Enable host networking" setting once (Settings → Resources → Network, Docker Desktop 4.34+), and the launcher warns, with those steps, when it isn't in effect. If uav-api's docs or a Ground Station can't be reached from Windows, fix that setting; don't add `-p`. Which process uses which port: `docs/network.md`.
